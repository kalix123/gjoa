# AGENTS.md — gjoa project guide

gjoa is a Firefox fork. Everything it adds is plain JavaScript (no compile
step of our own) plus a small set of engine patches. Details live in
[`docs/BUILDING.md`](docs/BUILDING.md); this file holds the rules.

## Layout

- `patches/*.patch` — C++/Rust changes to Firefox, applied in filename order.
- `src/gjoa/browser`, `src/gjoa/toolkit` — files overlaid onto the Firefox tree
  (loader, about: pages, actors, the content-classifier RS-client overlay).
- `src/gjoa/chrome/` — window chrome as ES modules, bundled by
  `scripts/chrome-bundle.mjs` per `bundles.json` into `.uc.js` scripts.
- `src/gjoa/defaults/pref/*.js` — default prefs appended to the branding pref file.
- `scripts/prepare.mjs` — builds `engine/` from the pinned Firefox tarball.
- `tests/` — `npm test` (Node's built-in runner, no dependencies).

## Rules

1. **Cheapest layer that owns the behaviour.** Prefer window chrome
   (`src/gjoa/chrome`, hot-reloadable) over overlaid `.sys.mjs` files, and
   those over engine patches. Patches conflict with every Firefox release.
2. **Don't start a full `./mach build` without the user's go-ahead** — it
   takes hours. `node scripts/prepare.mjs`, `npm test` and bundling are cheap.
3. **Never edit `engine/` by hand.** It is regenerated by `prepare.mjs`; put
   changes in `patches/` or `src/gjoa/`.
4. **Every patch must apply.** After changing a patch or the Firefox version,
   run `node scripts/prepare.mjs` and keep each patch's `baseline-firefox:`
   header current.
5. **Chrome modules use only relative named/namespace imports and
   `export function|const|let|class`** (what the bundler supports). Modules
   share nothing except through imports.
6. **Release is CI's job:** push a `vX.Y.Z` tag matching `gjoa.json`
   `displayVersion` with notes in `.github/release-notes/`; CI builds all
   platforms and drafts the release.

## Porting notes

The chrome code was ported from Beagle (a Clojure-like language) and some
modules still use `truthy()` / `equiv()` from `src/gjoa/chrome/lib/value.mjs`,
which keep Clojure semantics (only `null`/`undefined`/`false` are falsy;
`equiv` compares plain objects/arrays/sets by value). When cleaning a module,
replace them with plain JS only where the operand types make the semantics
identical (e.g. a DOM node or boolean), not blindly — `0` and `""` differ.
